# Decision 0001: Organize the repository as a living research atlas

- Status: accepted
- Date: 2026-10-11
- Supersedes: none

## Context

The projects in this trajectory do not form a single software package. They test different conditions for long-horizon mathematical work: local feedback, unfinished state, persistent worlds, organizational replaceability, and evidence.

A chronological list would hide the relationships between them. A monorepo would erase the fact that each project has its own apparatus, boundary, and history.

## Decision

Organize Researching Research as a living research atlas.

- Each repository receives a stable project card.
- The research arc and current questions remain hand-written and revisable.
- Mechanical project fields live in project-index.json.
- Fixed commit links carry historical evidence.
- A small script may generate the index table, but it must not generate research meaning or personal contribution.
- Major changes in interpretation receive numbered decision records.

## Consequences

Adding a new repository remains local: one card and one index entry can be reviewed independently. The README can stay stable while the project set grows.

The map may contain partial, negative, or adjacent work. That is intentional. A project is not promoted to the centre of the mathematical-agent story merely because it exists in the same GitHub account.
