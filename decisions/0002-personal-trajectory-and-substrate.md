# Decision 0002: make the personal trajectory primary

## Context

The first version of this atlas used a five-part abstraction that began with reliable local action and then moved through unfinished work, persistent worlds, replaceability, and evidence. That abstraction is useful as a map of the current problem space, but it can be misread as a preplanned workflow or as if large-scale swarm failure were the starting point.

## Decision

Keep the five-part map as a current abstraction. Add a practice-first research-development document and make the historical sequence explicit. Collaborative work may enter the project index when there is a distinct artifact, a real research role, and an auditable contribution boundary. It must be marked collaborative and must state what I did not contribute:

Putnam 2025 → Pi Math First Proof Swarm / Ralph loop → Pi Lean Tools → ContextSwarm / ContextSwarmJudge collaborative work → Metron → Persistent Mathematical Worlds / MathWeave → future research substrate.

Describe each stage as belief before, intervention, observation, belief after, and open question. Treat the future substrate direction as a short research-plan pointer, not as a claim about the original intent of the early projects. The repository should continue to evolve when a new artifact exists.

## Invariant

The invariant is the attempt to build a better environment in which an agent can use, preserve, and continue mathematical capability. The unit of inquiry expanded from tools and local feedback to shared state, evidence, persistent worlds, and protocols that might themselves be changed by experiments.

## Reversal condition

If later evidence shows that a different problem—not substrate evolution—better explains the useful work, this decision should be revised. The atlas should preserve that revision rather than protect the current vocabulary.
